# 04. 개발기획 (Development Plan)

> 핵심 흐름: **파일 업로드 → 데이터분석처리단계(7단계) → 보고서 작성**
> 원칙: 개발보다 검증이 먼저. 직접 만들기 전에 수작업(컨시어지)으로 팔려는지 확인한다.

## 1. 추천안 한눈에 보기

| 구분 | 추천 | 이유 |
|---|---|---|
| 1순위 | 수작업 MVP로 유료 보고서 5건 검증 | 개발비 0원, 1~2주, "돈 내고 받는 보고서"인지 확인 |
| 2순위 | 랜딩페이지 + 사전예약 | 개발 전 수요 확인, 정부지원사업 근거 자료 |
| 3순위 | 1~6단계 MVP 개발 (6주) | 검증된 흐름만 구현 |
| 4순위 | 7단계 자동화(n8n)·팀 기능 | 반복 사용 고객이 생긴 뒤 |

> 정부지원사업 적합성(창업 지원 프로그램 등)은 공고마다 요건이 달라 **지원 시점에 공고문 기준으로 확인 필요**합니다.

## 2. 린 검증 로드맵 (개발 전)

| 단계 | 기간 | 할 일 | 통과 기준(예시) |
|---|---|---|---|
| A. 시장 검증 | 1주 | 타깃 5~10명 인터뷰 (소상공인·마케터·1인 셀러). "엑셀 보고서에 쓰는 시간·불편" 질문 | 5명 중 3명 이상이 반복 고통 언급 |
| B. 수작업 MVP | 1~2주 | 고객 엑셀을 받아 Claude + 노트북으로 분석, 보고서 PDF를 직접 납품 | 유료 5건(또는 지불 의사 명시) |
| C. 랜딩·사전예약 | 1주 | 샘플 보고서·시안 이미지·대기자 등록 | 방문 대비 등록 전환율 기록 |
| D. 정부지원 검토 | 병행 | 사업계획서에 기획 문서·시안·검증 결과 활용 | 공고 요건 확인 |
| E. 정식 개발 | 6주 | 아래 마일스톤 | 첫 유료 사용자 |
| F. 자동화·확장 | 이후 | 7단계 파이프라인, 팀, 템플릿 | 재사용률 |

수작업 MVP에서 얻을 것: 자주 나오는 데이터 유형, 가장 가치 있었던 보고서 섹션, 정리 제안 중 실제로 눌리는 항목.

## 3. 범위

### MVP (6주)
- 로그인, 프로젝트 목록/대시보드 홈
- 업로드(CSV·XLSX, 끌어다 놓기), 검사
- 데이터분석단계 **1~6단계**, 체크포인트 2곳(목표 확인, 정리 제안 승인)
- 정리 제안 4종(날짜 통일, 상품명 정리, 결측 처리, 이상치) + 변경 전·후 미리보기
- 자동 대시보드(그래프 선택 규칙 적용), 3단계 반응형
- 보고서 미리보기 + PDF 내보내기
- 단계별 실시간 진행 표시

### v2
- Word 내보내기, 공유 링크
- 7단계 자동화(n8n 스케줄·알림), 파이프라인 저장
- 질문 창(자연어) 고도화, 위젯 직접 편집
- 팀·권한, 결제, 템플릿 마켓

### 제외(초기)
- 실시간 DB 연결, 대용량(50MB 초과), 머신러닝 모델 학습 UI

## 7. API 목록 (분석 서비스 / BFF)

| 구분 | 엔드포인트(요약) | 설명 |
|---|---|---|
| 업로드 | 서명 URL 발급, 업로드 완료 알림 | 원본 저장, 검사 시작 |
| 실행 | 실행 시작, 상태 조회, 단계 재시도 | 7단계 오케스트레이션 |
| 체크포인트 | 목표 확인, 제안 결정 전송 | 사용자 승인 반영 |
| 제안 | 제안 목록, 미리보기, 적용/건너뛰기 | 3단계 |
| 대시보드 | 위젯 spec 조회, 질문 전송 | 6단계 |
| 보고서 | 생성, 파일 조회, 공유 링크 | PDF(MVP), Word(v2) |
| 파이프라인 | 저장, 예약, 웹훅 수신 | v2 |

상태 전달은 Supabase Realtime을 사용하고, API는 실행 명령과 승인 위주로 최소화합니다.

## 8. 마일스톤 (6주, 1인 기준)

| 주 | 목표 | 산출물 | 완료 기준 |
|---|---|---|---|
| 1 | 기반 | 모노레포, 인증, 디자인 토큰, 레이아웃(GNB·반응형) | 로그인 후 빈 화면 3종 이동 |
| 2 | 업로드·수집 | 드롭존, 검사, 프로파일링(2단계), 데이터 버전 | CSV/XLSX 업로드 → 프로파일 표시 |
| 3 | 정리 | AI 계획→검증→미리보기→적용(3단계), 변경 이력 | 제안 4종 승인·되돌리기 |
| 4 | 분석·시각화 | EDA, 집계, 그래프 선택 규칙, 대시보드 | 샘플 3종 데이터에서 올바른 그래프 |
| 5 | 보고서·진행 | 인사이트 문장+검수 규칙, PDF, 7단계 애니메이션 연동 | 업로드→PDF까지 한 번에 |
| 6 | 안정화 | 오류 처리, 비용 한도, 보안 점검, 베타 5명 | 베타 피드백 반영 |

## 10. 품질·비기능 기준

| 항목 | 기준(목표) |
|---|---|
| 성능 | 5MB 파일 업로드→대시보드 표시 목표 1분 내(측정 후 조정) |
| 정확성 | 보고서 숫자는 원본 계산값과 100% 일치(자동 검수) |
| 안전 | AI는 계획만, 서버가 검증한 연산만 실행 |
| 복구 | 원본 불변, 단계별 재시도 |
| 접근성 | 키보드 이동, 색 대비, 차트 대체 텍스트 |
| 테스트 | 연산 단위 테스트, 그래프 규칙 표 기반 테스트, 샘플 데이터 3종 회귀 |

## 11. 비용·리스크

| 리스크 | 영향 | 대응 |
|---|---|---|
| AI 호출 비용 증가 | 마진 하락 | 요약만 전송, 캐시, 사용자 한도 |
| 이상한 데이터 형식 | 실패율 | 업로드 검사, 실패 시 사유 안내 |
| AI가 틀린 문장 작성 | 신뢰 하락 | 숫자 자동 검수, 근거 연결 필수 |
| 개인정보 포함 | 법적 부담 | 마스킹 옵션, 삭제 기능, 고지 |
| 경쟁(Tableau·Power BI·Looker Studio) | 차별 필요 | "업로드→보고서까지" 단순함과 한국어 보고서 품질 |
| 1인 개발 일정 | 지연 | 6주 범위 고정, v2 분리 |
