# 01. 서비스 기획서 — Analytics Flow Studio

> 파일을 올리면 **7단계 데이터분석처리**를 거쳐 **보고서**가 만들어지는 AI 데이터 분석 서비스
> 작성일 2026-10-24 · 상태: 기획 초안 (디자인 시안 반영) · 서비스명은 가칭(레포명 기준)

---

## 1. 한 줄 정의

CSV·엑셀 파일을 올리면 AI가 **문제 정의 → 수집 → 전처리 → 탐색 → 분석 → 시각화 → 자동화**의 7단계를 대신 진행하고, 사람은 중요한 지점에서만 확인하면 **대시보드와 보고서(PDF·Word)** 가 완성됩니다.

## 2. 문제와 기회

| 구분 | 내용 |
|---|---|
| 대상 | 소상공인·이커머스 셀러·1인 사업자·마케터·소규모 팀 (데이터 전문가가 없는 곳) |
| 현재 방식 | 엑셀 수작업, Tableau·Power BI 학습·라이선스 부담, 분석 후 보고서를 또 따로 작성 |
| 문제 | ① 데이터 정리에 시간이 가장 많이 듦 ② 어떤 그래프를 써야 할지 모름 ③ 분석과 보고서가 분리됨 |
| 기회 | LLM이 "분석 계획"을 세우고, 서버가 검증된 연산만 실행하면 **정확성과 속도를 동시에** 확보 가능 |
| 차별점 | 분석 과정을 7단계로 **보여주면서(투명성)** 진행하고, 정리 이력이 보고서 부록으로 남음(근거 추적) |

## 3. 핵심 사용자 흐름 (한 문장)

**파일 업로드 → 데이터분석처리단계(7단계) → 대시보드 → 보고서 작성**

```
업로드 ──► [1 문제정의] ► [2 수집] ► [3 전처리] ► [4 EDA] ► [5 모델링] ► [6 해석·시각화] ► [7 자동화]
                                        ▲사람 확인          ▲사람 확인        │
                                                                          ▼
                                                                대시보드 + 보고서(PDF/Word)
```

- **보고서는 별도 작업이 아닙니다.** 6단계의 산출물(지표·차트·인사이트)과 3단계의 정리 이력을 그대로 조립해 만듭니다.
- 사람이 개입하는 지점은 두 곳(① 목표 확인, ② 정리 제안 승인)이 기본이며, 나머지는 자동 진행합니다.

## 4. 7단계 데이터분석처리 정의

각 단계는 **입력 → 처리 → 산출물 → 사용자 확인** 으로 정의하며, 산출물은 모두 DB에 저장되어 다음 단계와 보고서에서 재사용됩니다.

| 단계 | 입력 | 시스템 처리 | 산출물 | 사용자 확인 | MVP 범위 |
|---|---|---|---|---|---|
| 1. 문제 정의·목표 설정 | 프로젝트 이름, (선택) 목표 문장 | 컬럼 요약을 보고 KPI·가설 후보 제안 | `analysis_goal` (KPI, 가설, 기간) | **필수**: 목표 확인·수정 | ✅ |
| 2. 데이터 수집 | CSV·XLSX 파일 | 인코딩·시트·구분자 감지, 컬럼 유형 추정, 프로파일링 | `dataset`, `profile` | 자동 | ✅ 파일만 (DB·API는 v2) |
| 3. 전처리·정제 | 원본 데이터셋 | AI가 정리 제안(JSON) 생성 → 서버 검증 → 승인 항목만 실행 | `cleaned_dataset`, `change_log` | **필수**: 제안별 적용/건너뛰기 | ✅ |
| 4. 탐색적 분석(EDA) | 정제 데이터 | 분포·상관·결측·범주 비율 계산, 그래프 추천 규칙 적용 | `eda_summary`, `chart_candidates` | 자동 | ✅ |
| 5. 모델링·심층 분석 | 정제 데이터 + 목표 | 집계·추세·채널 비교·이상 탐지(MVP), 예측·군집(v2) | `analysis_results` | 자동 | ✅ 기본 통계 / v2 예측 |
| 6. 결과 해석·시각화 | 분석 결과 | 대시보드 위젯 구성, AI 인사이트(근거 포함) 작성, 보고서 조립 | `dashboard`, `report` | 선택: 말로 수정 | ✅ |
| 7. 자동화·파이프라인 | 완료된 실행 | 같은 설정으로 재실행, 예약·알림 | `pipeline`, `schedule` | 설정 시 1회 | v2 (n8n 연동) |

### 4-1. 사용자 확인 지점(Checkpoint) 원칙

1. **필수 확인은 최소화**: 목표(1단계)와 데이터 변경(3단계)만. 데이터를 바꾸는 일은 반드시 사람이 승인합니다.
2. **원본 불변**: 정제는 새 버전(`dataset_version`)으로 저장하며 언제든 되돌릴 수 있습니다.
3. **AI는 계획만, 실행은 서버**: AI가 낸 JSON 계획을 서버가 스키마·화이트리스트로 검증한 뒤 코드를 실행합니다(임의 코드 실행 없음).
4. **근거 표시**: 인사이트 문장마다 근거 지표·차트를 연결해 "왜 이런 말을 하는지" 확인 가능.

## 5. 보고서 설계

| 섹션 | 데이터 출처 | 비고 |
|---|---|---|
| 표지 | 프로젝트명, 기간, 작성일 | 브랜드 로고 영역 |
| 핵심 요약 | 6단계 AI 요약 | 3~5문장, 숫자 근거 링크 |
| 목표 대비 결과 | 1단계 KPI × 5단계 결과 | 불릿 차트(목표 대비) |
| 핵심 지표 | 6단계 KPI 카드 | 증감 포함 |
| 분석 결과 | 4·5단계 차트 | 데이터 조합별 자동 선택(그래프 구조 문서 참조) |
| 해석과 제안 | 6단계 인사이트 | "그래서 무엇을 해야 하는가" 형식 |
| 데이터 품질·정리 이력 | 3단계 `change_log` | 부록. 신뢰도 근거 |
| 부록 | 컬럼 설명, 분석 설정 | 재현 가능성 확보 |

- 출력: **화면 미리보기(A4) → PDF · Word 내보내기**, 링크 공유(읽기 전용).
- 같은 데이터로 재실행하면 보고서가 **새 버전**으로 생성되고 이전 버전은 보관됩니다.

## 6. 그래프 선택 규칙(요약)

컬럼 유형(날짜·숫자·범주)과 항목 수에 따라 자동 선택하고 사용자가 바꿀 수 있습니다. 상세 표는 `design/Charts.dc.html`(리포트 · 그래프 구조) 참고.

| 데이터 조합 | 기본 | 대안 |
|---|---|---|
| 날짜 + 숫자 1 | 선 | 영역 |
| 날짜 + 같은 단위 숫자 2~4 | 다중 선 | 누적 영역 |
| 날짜 + 단위가 다른 숫자 2 | 콤보(이중 축) | 작은 다중 그래프 |
| 범주(≤7) + 숫자 | 세로 막대 | 도넛(합계 100%일 때) |
| 범주(8~20) + 숫자 | 가로 막대(정렬) | 표 |
| 범주(21+) + 숫자 | 상위 10 + 기타 | 검색 가능한 표 |
| 범주 2 + 숫자 | 묶음·누적 막대 | 히트맵 |
| 숫자 1 (분포) | 히스토그램 | 상자 그림 |
| 숫자 2 (관계) | 산점도 | 버블(숫자 3) |
| 목표값 있음 | 불릿 | 게이지 |

예외 처리: 데이터 없음, 행 5개 이하(→표), 범주 과다, 음수 포함, 결측 구간(선 끊기), 이상치(강조·제외 토글), 값 편중(로그 축 제안), 단위 혼합(이중 축/분리), 로딩·오류.

## 7. 화면 구성 (디자인 시안 기준)

GNB: **대시보드 → 업로드 → 프로젝트 → 데이터분석단계(하위 7단계) → 리포트**

| 화면 | 시안 파일 | 경로(안) | 설명 |
|---|---|---|---|
| 대시보드(시작 화면) | `Home.dc.html` | `/dashboard` | 프로젝트 수, 최근 프로젝트, 이어서 할 일, 사용량, 활동 |
| 업로드 | `Upload.dc.html` | `/upload` | 드래그앤드롭, 파일 상태, **데이터분석하기** 버튼 |
| 프로젝트 목록 | `Projects.dc.html` | `/projects` | 상태 필터, 단계 진행, 진행 내용 요약 |
| 데이터분석단계 | `Steps.dc.html` | `/projects/[id]/analysis` | 7단계 진행 애니메이션, 단계별 설명·바로가기 |
| 3단계 전처리·정제 | `Check.dc.html` | `/projects/[id]/analysis/cleaning` | 컬럼 요약, 정리 제안 4종(접기/펼치기, 변경 미리보기), **프로젝트 만들기** |
| 프로젝트 상세 | `Main.dc.html` | `/projects/[id]` | KPI, 추이, 비중, ROAS, 상위 상품, AI 수정 채팅 |
| 생성 결과(벤치마킹 구성) | `Generated.dc.html` | `/projects/[id]/dashboard` | 질문 창, 탭, 필터 창, 인사이트, 근거 |
| 리포트 | `Report.dc.html`, `Charts.dc.html` | `/projects/[id]/report` | A4 미리보기, 그래프 구조 |
| 태블릿·모바일 | `DashboardTablet/Mobile.dc.html` | 동일 | 반응형 변형 |

반응형 기준: 모바일 ~767 / 태블릿 768~1199 / 데스크탑 1200~ (글자: 본문 14·15·16, 제목 20·24·28, KPI 24·28·32).

## 8. 벤치마킹 정리

공개된 기능 방식에서 **패턴만** 참고했고 화면 디자인은 따라 하지 않았습니다. (최신 사양은 도입 전 공식 문서로 재확인 필요)

| 서비스 | 참고 패턴 | 적용 위치 | 우리의 차별점 |
|---|---|---|---|
| Power BI | 필터 창, 교차 필터, 질문(Q&A) | 필터 창 / 질문 창 | 정리 이력으로 숫자 근거 확인 |
| Tableau | 시트 탭, 드릴다운, 지표 설명 | 탭, 월/주 전환 | 설정 없이 말로 수정 |
| Looker Studio | 기간 컨트롤, 공유 | 기간 칩, 공유 | 문장형 리포트 자동 작성 |
| ThoughtSpot | 검색형 질의→답변 카드 | 질문 창→고정 | 추천 질문 자동 제안 |
| Metabase | 업로드 직후 자동 탐색 | 생성 완료 안내 | 점검·승인 단계로 오류 감소 |

## 9. 수익화 가설 (검증 대상)

| 모델 | 내용 | 비고 |
|---|---|---|
| 건당 리포트 | 파일 1건 분석 + 보고서 1건 | 가장 빠른 첫 매출 (수작업 MVP로 검증) |
| 월 구독 | 프로젝트 N개, AI 질문 N회, 내보내기 N건 | 시안의 "이번 달 사용량" 구조와 일치 |
| 화이트라벨 | 에이전시·세무/회계 사무소가 고객에게 제공 | 반복 매출·계정 확장 |
| 설치형·맞춤 | 업종별 템플릿(이커머스, 광고, 재고) | 템플릿 판매 |

가격은 시장 검증(인터뷰·사전예약) 이후 확정합니다. 임의 가격을 이 문서에 확정하지 않습니다.

## 10. 성공 지표 (MVP)

| 지표 | 목표(초안) | 측정 |
|---|---|---|
| 업로드→보고서 완료율 | 60% 이상 | 실행 이벤트 |
| 첫 보고서까지 시간 | 10분 이내 | 실행 로그 |
| 정리 제안 수락률 | 70% 이상 | 제안별 결정 로그 |
| 보고서 내보내기 비율 | 완료 프로젝트의 50% 이상 | 내보내기 로그 |
| 유료 전환(수작업 단계) | 5건 | 결제 기록 |

## 11. 용어

- **프로젝트**: 파일 묶음 + 분석 실행 이력 + 대시보드 + 보고서의 단위
- **실행(Run)**: 7단계를 한 번 진행한 기록. 재실행하면 새 Run이 생김
- **제안(Proposal)**: AI가 만든 정리 계획의 한 항목. 사용자가 적용/건너뛰기 선택
- **파이프라인**: 7단계 설정을 저장해 다시 돌릴 수 있게 한 것(7단계)
